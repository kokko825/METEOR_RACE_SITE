# 2026-09-18 待機ルーム・検索公開検査

## 待機ルーム（1.0.85）

- 原因：開始・退出ボタンの sticky 配置がCPU設定を覆っていた。スマホでもメンバー2列・CPU設定横詰めを維持し、文字拡大時の余裕がなかった。
- 修正：ボタンを通常フローへ戻し、親の中央寄せグリッドをスクロール可能なブロックへ変更。個人戦のスマホはメンバー1列、チーム戦は左右2列を維持。難易度と人数操作の横幅を確保し、狭い幅は縦へ折り返す。
- ローカルChromium：日英×個人/チーム×6画面サイズ×3文字サイズの72条件で重なり・横はみ出し・難易度/人数/開始/退出のヒットテスト成功。
- 投稿画像と同じCPU2体を追加した状態を390×670で撮影し、設定と開始/退出が下部バーに隠れず表示されることを確認。
- iPhone実機Safariでの確認は未実施。ブラウザ模擬検査と区別する。
- `npm run check` 成功（ルール、AI smoke、UI、41構造テスト、ビルド含む）。

## 検索公開（本番を読み取り）

- `/`、`/guide`、`/items`、`/policy`、`/updates` は200、HTML内に本文を含み、index/follow、ページ固有の正規URLを返す。
- `/robots.txt` はトップと公開ページを許可。`/sitemap.xml` はXMLで5ページを列挙。
- 旧 `/privacy`、`/terms` は `/policy` へ転送。旧URLが単独登録されないことは異常ではない。
- 更新履歴のサイトマップ更新日が9月8日のままだったため、リリースノートの先頭日付へ連動。ほかのページの日付は実際に本文が変わった際のみ更新する。
- 通常HTTP取得に基づく検査。Googlebotの実IPからのアクセスやSearch Consoleの最新状態は未確認。技術的条件の通過はGoogleのインデックス登録を保証しない。
- 次の切り分けにはSearch ConsoleのトップURL検査結果の「未登録理由」「前回のクロール」「Googleが選択した正規URL」と公開URLテスト結果が必要。

メール関連のDNS・転送設定には変更を加えていない。
