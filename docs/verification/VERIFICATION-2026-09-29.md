# 1.0.86 検証記録（2026-09-29）

## 修正

- オンライン退出処理で観戦席のnullを除いてしまい、残ったメンバーの席がずれる問題を修正。
- 開始時は現在の席を採用し、過去の席情報で交換を巻き戻さない。
- CPU人数と盤面サイズの正規化を共通化し、参加人数との食い違いを修正。
- ルーム作成時のCPU難易度を保持。旧チーム変更APIにもホスト権限チェックを適用。
- 待機設定の応答はメンバー情報も反映し、既に破棄された画面の応答を適用しない。
- EASYの配置だけに残っていた厳しすぎる候補フィルターを撤去。設定済みの難易度選択処理に統一。

## 検証結果

- `npm run check` 成功：lint、型、設定、素材、ルール、投稿データ、アイテム、AIスモーク、UI、41件の構造検査、production build。
- `npm run test:ai:quality` 成功：21条件×3難易度×4試合＝252試合、難易度比較160試合。通常・アイテム・チーム・チームアイテム・ランクを含む。
- 色を入れ替えた追加比較96試合も完走。以上508試合。これは有限の固定seed検証で、全局面の安全性や人間の面白さを保証しない。
- 通常9×9：NORMAL対EASYは赤NORMAL44/48勝、青NORMAL44/48勝。HARD対NORMALは赤HARD29/32勝。
- アイテム11×11：NORMAL対EASYは赤NORMAL37/48勝、青NORMAL32/48勝。HARD対NORMALは赤HARD30/32勝。
- ローカルルームAPI：参加、観戦、退出、席交換、権限、人数、盤面、難易度を3回反復して成功。
- ローカルEdgeの表示検査：日英×個人/チーム×6画面サイズ×3文字サイズ＝72条件で待機ルーム操作の重なり検査に成功。
- チュートリアル：タイトル・モード選択・対戦設定の3入口から直接開始し、異なる初手、固定CPU行動、自由行動での案内終了、ホーム帰還を確認。初期テストの演出中の同期判定によるタイムアウトは、次の操作可能マスを待つ方式に修正。最後のCORE到達までの全経路は未検証。

## テスト方法と限界

`tests/integration/online-room.integration.mjs`、`tests/browser/lobby-layout.browser.mjs`、`tests/browser/tutorial.browser.mjs` は起動中のローカル開発サーバーに対して実行する。実データへの書き込みを避けるためlocalhostに限定する。

AI後退率は総数を残しつつ、全ての移動先がCOREから遠ざかる強制後退を別計上する。EASYの自発的な後退ゼロも検査する。

実機iPhone/Safari、複数の実回線、切断復旧の全組合せは今回未検証。本番不具合報告DBはCloudflare認証エラー7403で読めず、届いた報告を全件修正したとは扱わない。BGM休止は維持し、DNS・メール設定は変更しない。
