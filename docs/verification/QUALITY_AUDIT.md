## 2026-11-01 4人戦の停滞改善（1.0.115）

### 原因と採用判断

- 前進を徐々に重視する補正はHARD・4人残存時のみで、NORMALにはなく、先着者が出るとHARDでも途切れていた。4人で始まった個人戦のNORMAL／HARDへ適用し、残り順位争いでも継続する。
- 相手の前進への減点を単純に弱めた試案では、既知の長期戦4試合のうち3試合が引分のままだった。利敵行為への減点は維持する。前進補正をさらに加速する試案も別条件で安定せず採用しない。
- 残り順位の自動確定を自分のCORE到達と同じ成功にしていたため、相手をゴールさせて終える行動が選ばれた。実際にCOREへ到達した場合だけ順位成功として評価する。2位・3位の自力ゴールは引き続き高く評価する。
- 基本27条件の妨害メテオ割合は51.2%→48.6%、自分を進める配置は24.5%→28.3%。両方を兼ねる配置を含む。妨害を消して短縮したものではない。ゲームルール・装備性能・時間切れ条件は変更しない。
- 3人戦・チーム戦の回帰各6条件は記録が完全一致。前進補正の対象拡張は4人個人戦のみ。自動順位評価の修正は個人順位戦で共通。

### 検証と限界

追加回帰：100手経過時のNORMAL／HARD、先着0／1／2人の各状態で、自分のCORE到達と相手の即時ゴール阻止を確認。既存の次手予測・効果失効・防御委任・自滅PULSE回避も通過。`npm run check`（ルール、AI、UI、型、lint、ビルド）を反復し成功。

全条件で短縮する保証はない。別乱数では平均が悪化し、1試合が時間切れになった。採用版にも118手の試合が残る。人間同士の妨害戦術、混合難易度、実機・実通信、人による楽しさの評価は今回の試験対象外。開始位置は追加条件で変えているが、全方位・全組合せの網羅ではない。

再現：`node tests/run-multiplayer-pacing.mjs`。`PACING_POLICY=baseline` で1.0.114、`current`で作業版。既定27条件。通常戦は `PACING_MODE=classic`、12条件は `PACING_CASES=14,18,22,26,30,34,50,54,58,62,66,70`、別乱数は `PACING_SEED_OFFSET=997`。3人・チーム回帰は先頭6条件に `PACING_PLAYERS=3` または `PACING_MODE=team-item`。結果の保存先は `.cache/tests/multiplayer-pacing/<PACING_SUITEまたはpolicy>/results.json`。`PACING_SUITE`で比較結果を区別する。

## 現行の設計

- 小さい文字で収めず、アイテム旗は選択した1件の説明を読みやすく表示する。狭い画面の選択中は説明と選択操作を優先する。
- 遊び方は移動後にメテオ・アイテム・ボーナス移動を選ぶ関係を示し、爆風の距離別強度を図示する。
- チームの旗を同じ側へまとめ、チーム名で区別する。複数イベントは横並びに表示し、予告の場所・方向を併記する。
- タッチ操作は実ルールで対象と結果を予告し、確定まで状態を変更しない。PCマウスは従来の直接操作を維持する。
- 遠距離では前進と布石を評価するが、次手にゴールできる敵の阻止を優先する。小盤面では距離が遠そうでも爆風で勝てるため、序盤妨害を一律禁止しない。

## 今回直した問題

- EASYが弱いのではなく不自然に後退していた問題：前進・横移動が可能ならランダム後退を除外
- NORMALの11×11アイテム戦で後退率43.4%だった問題：明確な利益を証明できる後退だけ許可し0.6%へ改善
- 難易度差が見えにくかった問題：理解できる行動を保ったままEASYの候補幅と防御精度を調整
- HOLOなどの説明画像に古い巡数が残り得る問題：変動する数値を重複記載せず、設定由来の本文を唯一の数値表示に変更
- プレイヤー画面に旧AI LAB、重複HOW TO PLAY、非表示MISSION LOGが残っていた問題
- `page.tsx` に駒・所持欄の表示実装まで集中していた問題：`components/game-pieces.tsx` へ分離
- スマホ待機室が人数増加時にクリップされ得る問題：スマホだけ安全に縦スクロールへ退避
- タッチ端末の小さい操作領域とキーボードフォーカス不足
- READMEに存在しないPC内フォルダを正本と書いていた問題：GitHub `main` が正本であることを明記
- 保存設定が初回描画時の初期値で上書きされ得た問題：読み込み完了後だけ保存するよう統一し、不正な音量・曲名も安全な値へ補正
- チーム戦の研究用判定が味方への影響を妨害として扱い得た問題：敵チームだけを評価対象に修正
- 研究用好プレーの点数を送信側が改変できた問題：サーバー側の盤面再計算と一致したものだけ保存
- CPUのアイテム選択が機体ごとに似通って見えた問題：REDは前進、BLUEは制御、GREENは盤面操作、YELLOWは防御・回収を好む個性を追加
