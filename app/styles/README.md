# スタイルの編集先

`app/globals.css` は読み込みの入口だけです。次の順序を変更しないでください。

1. Tailwind
2. `responsive-safety.css`：スクロール・操作性の基本安全設定
3. `game-interface.css`：配色、駒、各画面・部品の基本表示と既存の画面別調整
4. `layout-overrides.css`：共通下部バー、文字サイズ、盤面と操作欄、待機ルームなどの最終配置調整

今回の分割では、既存のセレクター・値・上書き順を維持しています。
画面別の古い調整も残るため、後ろへ同じ指定を追記する前に、関連セレクターを両方のファイルで検索してください。
同じセレクターでも端末条件や順序に意味があるので、一括削除・並べ替えはしません。

盤面比率や安全な余白の数値は、まず `config/ui-layout.ts` を確認します。
新しい画面を作らない限り、部品ごとの小さなCSSファイルは増やさず、既存の該当セクションを修正します。

検査は `npm run check`。実際のサイズ・重なりはPC、タブレット、スマホ縦でも確認してください。

待機ルームは `layout-overrides.css` 末尾で配置を確定します。外側の `.control-strip` だけをスクロールさせ、開始・退出ボタンは通常の文書フローに置きます。下端への固定はCPU設定を覆うため使用しません。

ブラウザ回帰検査：ローカル開発サーバーを起動後、`node tests/browser/lobby-layout.browser.mjs`。PlaywrightとChromiumが必要です。共有インストールの場合は `PLAYWRIGHT_MODULE` と `TEST_BROWSER_PATH` で指定できます。公開サーバーでは実行できないよう制限しています。日本語・英語、個人・チーム戦、3 CPU、6画面幅、3文字サイズの72条件で領域の重なりと主要操作のヒットテストを検査します。実機Safariの検査は別途必要です。

対戦画面は `layout-overrides.css` の「Device-specific battle composition」で端末別に配置します。900px以下は参加者を盤面の上に2列で表示し、PCは左右の旗を中央寄せにします。盤面は移動・メテオ・アイテムの操作変更で縮小させません。所持アイテム1個の数値だけを省略し、2個以上は表示します。拡大文字・小さい画面では重なりを避けてスクロールできます。

対戦配置の回帰検査：`node tests/browser/battle-layout.browser.mjs`。`TEST_ORIGIN` はローカルサーバー（既定は3000番）を指定します。2〜4人・個人/チーム・通常/アイテムの7構成、5画面幅、2文字サイズ、手番変更時の盤面寸法と配置ボタンの到達性を確認します。通信・Safari実機の保証とは別です。

PCの背景・旗の反応は同じCSS節の `battle-atmosphere` と `flag-acquire` で調整します。背景は入力を受け取らず、レイアウトの寸法に影響しません。所持品変化の短い反応は `game-pieces.tsx` の `InventoryPanel` にあります。端末の動きを減らす設定では新しい演出を停止します。

反応演出の回帰検査：`node tests/browser/battle-feedback.browser.mjs`。上記と同じブラウザ設定を使い、実際のメテオ消費、初期表示の誤反応防止、背景の入力透過、動作軽減、スマホの背景非表示を確認します。
